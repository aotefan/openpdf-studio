# OpenPDF Studio architecture decision
React + TypeScript + i18next renders a ribbon, thumbnails, document canvas, object inspector and modal previews. Electron provides native file dialogs and an isolated preload bridge (contextIsolation, sandbox, nodeIntegration=false). A persistent Python worker receives allowlisted JSON requests over stdio, accepts bytes and session IDs, never arbitrary executable code. MuPDF handles rendering and editing; pypdf is an independent QA parser. Apple Vision provides optional offline OCR via a small Swift helper.
Tauri evaluated: requires absent Rust toolchain. Electron chosen for a verifiable desktop path and Playwright automation; engine boundary permits a future Tauri adapter. All runtime processing local; no model/network upload integration in this milestone.
Engine stores source bytes and bounded undo/redo snapshots. Every edit builds a candidate copy first, returns render/difference summary and requires Apply. Commit is revision-checked; failure leaves the active document unchanged. Exports are new files via native dialogs. Original files never opened for writing by engine.
Fonts: same-font direct object editing only for proven-safe cases; initial fallback is local text removal/reconstruction with explicit preview, overflow rejection and unaffected-region pixel comparison. This is not universal lossless PDF editing. Encrypted/restricted documents rejected; signatures flagged/rejected for editing. Large-file memory/tiling is later work.
