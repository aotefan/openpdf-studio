# 交互规范：最小步骤 / Minimum-step interactions

用户于 2026-10-15 明确要求后续开发遵循最小步骤原则。中文界面优先，英文语义与路径一致；本规范适用于新增功能和现有功能调整。

1. 可撤销、参数已明确的操作直接生效。后台生成候选、权限校验、排版差异检查和 revision 校验不等于用户必须点击“预览”和“确认”。失败保持原文档并说明原因。
2. 参数操作在同一窗口完成；主按钮应用一次即完成。可选效果预览为次要入口，不应成为默认必经步骤。主操作放在窗口底部右侧。
3. 批量操作先显示作用范围、匹配数量或变更摘要，再执行一次。已在页面管理中可见的选择/页序、关键词批注匹配清单，都是有效的事前摘要，不再机械重复弹出一个确认框。
4. 需要人工判断的 OCR 识别结果、可能重建原文字排版的全文替换，保留结果核对；逐步把预览整合到原设置窗口，避免串联弹窗。不能为了减少点击而静默忽略排版风险。
5. 关闭未保存文档、覆盖现有文件、权限不足等有实际后果的交互单独处理。已有明确用户授权不再重复请求权限。
6. 一次操作对应一条可撤销历史；失败不产生虚假成功、草稿丢失或部分修改。按钮执行期间防止重复提交。
7. 验收测量实际点击路径、弹窗次数、PDF 结果、撤销和保存重开，不能只改按钮文案。中英分别测试，小窗口操作按钮必须可访问。
8. WPS 只记录实际观察的版本和行为；会员受限的后续行为标未知。OpenPDF Studio 的改动来自独立代码。不要把截图相似或资源命令名当作功能还原证据。

后续页码设置扩展应采用“范围/格式/位置 + 同窗口预览或摘要 + 应用一次”，不得实现“设置 → 强制预览窗口 → 再次确认”的默认链路。
